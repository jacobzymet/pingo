    What can stop a real connection?
    • Firewalls on both computers and routers. Allow inbound IPv4 ICMP echo requests (type 8) from the peer on the active network profile. An app exception or echo-reply rule alone may not be enough. Keep the firewall enabled.
    • NAT and isolated Wi-Fi. Pingo has no NAT traversal. A router’s public IPv4 and TCP/UDP port forwarding do not make ICMP reach your computer. Private addresses need a shared LAN or routed private network. Guest Wi-Fi, client isolation and carrier NAT can prevent delivery.
    • Addresses and other VPNs. Use each computer’s real outer IPv4, not its Pingo tunnel IP. DHCP, Wi-Fi changes and another VPN can change addresses or routes. Update both configurations when an address changes.
    • Matching peers. Use the same shared key and matching Pingo versions. Start Receive for messages/files, or a VPN responder for VPN mode. Keep keys private and use one instance per endpoint/key.
    • Ping is not proof. A router or kernel can answer ordinary ping without Pingo working. Both peers send their own echo requests. ICMP inspection, rate limits, NAT identifier changes and low path MTU can break larger transfers even after a handshake succeeds.
    • Slow or interrupted transfers. Direct transfers wait for an acknowledgment for each fragment; latency and loss limit speed. Keep both computers awake. Files can resume by sending the same file again; check the receiver before retrying a failed message to avoid sending it twice.
    • VPN exits and recovery. Use different tunnel IPs on the same subnet, separate from either LAN. The exit needs forwarding, firewall rules, return routing or NAT, and working DNS. Default routing covers IPv4. A kill switch blocks outside traffic, including IPv6, and can stay active after failure; use recovery below.
    • Private data and traces. Use networks you administer. Received files and partials are plaintext on disk; protect the receive folder. Trace exports contain sensitive metadata. Share them privately.
    Restore connectivity after a VPN failure

    A VPN kill switch can keep outside traffic blocked after a failure. Stop the VPN first, then remove Pingo’s retained protection. This allows ordinary traffic again.
